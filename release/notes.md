# v3.31.0

## 升级说明

- 插件 `middleware` 合同由 v5 升至 v6，`upstream_adapter` 由 v4 升至 v5，不再接受这两项能力的旧合同；使用相关能力的插件需更新 SDK、清单和实现并重新构建后再升级宿主
- 上游适配器的每个注册项必须显式提供 `account_ids`，空数组表示匹配所有符合权限的账号；账号范围只收窄既有绑定，不扩大 Key、分组或模型权限
- Client Key 费用改为后台批量结算，已用金额在落库后显示；预算准入同时计算已落库金额和当前进程待结算费用，存储不可用、检查超时或结算积压达到上限时返回 `key_budget_unavailable`

## 新增能力

- 插件可在 attempt 阶段修改本次 Provider 构造参数；OpenAI 原生 Responses、Images、Search 和 Live 创建请求支持选择 `installation_id`，不改写账号凭据或实际计费归属
- 新增 `outbound` 中间件阶段，可在原生请求构造完成后组合 HTTP 方法、目标、完整多值头和二进制正文，或 WebSocket 候选握手与完整文本消息；准备链全部返回后才发送，覆盖 OpenAI 原生模型请求及 xAI 生成与压缩
- 上游适配器支持按账号选择，同一公开模型下不同账号可使用不同适配器，未匹配账号保留原生执行；xAI 原生编码不支持的请求也可交给符合范围的适配器

## 修复与调整

- 修复 OpenAI 受管上游适配路径未复用会话亲和和轮次关联的问题，保留 Client Key 隔离、根会话迁移与严格子会话限制，插件改写的请求仍原样交给适配器
- 修复 reasoning 分段的重复登记及摘要索引处理，保留原始 SSE／WebSocket 事件与类型冲突诊断
- 修复 OpenAI WebSocket 异常清理等待阻塞发送的问题，停止发送任务并释放连接后再归还容量
- 统一诊断快照生成与持久化的 128 KiB 上限，完整编码超限时优先淘汰普通事件，避免辅助诊断阻断请求终态写入；补充额度、账号反馈和策略处理耗时
- 账号与 API Key 列表记住本地排序偏好；精简管理端操作文案，改善侧栏折叠提示、账号额度、主题设置和用量页面的窄屏布局
- 更新 crypto-bigint 与 Tokio，修复 RUSTSEC-2026-0387、RUSTSEC-2026-0386 对应安全问题

## 性能优化

- Client Key 费用由后台任务按 Key 批量写入，响应交付和并发释放不再等待费用落库
- 减少 Responses WebSocket 请求正文与响应帧的重复复制，保留原有终态交付顺序
- 界面语言资源按需加载并缓存，快速连续切换时以最后一次选择为准
