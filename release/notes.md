# v3.29.6

## 修复与调整

- 修复 OpenAI 池化 WebSocket 慢建连被误计为熔断失败的问题；超过 800 毫秒时当前请求仍回退 HTTP/SSE，后台按实际建连结果更新熔断状态，避免连续慢成功或半开探测触发错误熔断
- 改进明确未发送请求的瞬时 HTTP 连接失败恢复：先在原账号重试，允许换号时为后续账号保留时间和连接次数；原账号再次建连失败时尝试其他账号，无可选账号时使用原账号的剩余预算，所有尝试仍共用最多 4 次建连、30 秒窗口
- 修复插件上游适配器持续接收数据的流在初始 RPC 预算耗尽后被截断的问题；初始流式回复后按模型请求期限、取消与单次读取预算管理流的寿命
- 管理端 S3/R2 备份改为流式压缩的业务归档，保留账号、Key、设置、插件、已用额度和已发布用量汇总，减少请求历史带来的备份体积与暂存空间占用；备份记录页补充范围说明
- 加快历史清理，每轮有界清理结束后一分钟继续检查；优先清理最旧记录并跳过被锁定的行，为单批清理设置锁等待与执行期限

## 升级说明

- 新建备份为 `.sql.gz`，使用 `gzip -dc` 解压并通过 `psql` 离线恢复到空目标库；此前生成的 PostgreSQL custom 格式归档仍使用 `pg_restore` 恢复
- 业务备份不包含请求明细、诊断与审计日志。原生历史仅保留全局小时用量，不支持恢复历史请求详情、按 Key/账号筛选或延迟分布；需要完整历史时请另做整库备份
- 原生用量汇总仅覆盖快照中已发布且尚未被历史清理撤销的统计；统计重建或时间桶尚未发布完成时备份会失败，需在统计就绪后重新创建
